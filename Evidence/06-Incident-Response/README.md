# Incident Response Evidence

## Overview

This section documents the incident response activities performed during the SOC and SIEM Threat Hunting and Incident Response project.

Security alerts and endpoint telemetry collected by Wazuh were analyzed to determine the affected systems, accounts, security events, and appropriate response actions.

## Incident Response Process

The investigation followed the standard incident response lifecycle:

1. Identification
2. Analysis
3. Containment
4. Eradication
5. Recovery
6. Lessons Learned

## Identification

Wazuh security alerts were reviewed to identify suspicious or security-relevant activity.

Priority was given to events involving:

- Repeated authentication failures
- Privileged logons
- Linux sudo-to-root activity
- Account creation and modification
- Local Administrators group changes
- Controlled data-transfer activity

## Analysis

Security events were correlated using:

- Wazuh rule IDs
- Windows Security Event IDs
- Linux journal and audit records
- User accounts
- Agent information
- Timestamps
- Authentication activity
- Privilege-related activity

This helped establish the sequence and context of the observed activity.

## Containment

For a real security incident, appropriate containment actions would include:

- Isolating the affected endpoint
- Disabling suspicious accounts
- Terminating unauthorized sessions
- Restricting suspicious network activity
- Preserving relevant security evidence

During this controlled lab exercise, testing activity was stopped after detection and validation were completed.

## Eradication

Potential eradication actions include:

- Removing unauthorized accounts
- Removing unauthorized group memberships
- Terminating malicious processes
- Removing persistence mechanisms
- Correcting insecure configurations
- Resetting compromised credentials

## Recovery

Recovery activities include:

- Validating endpoint security
- Restoring required services
- Confirming legitimate account access
- Verifying secure configurations
- Continuing enhanced monitoring through Wazuh

## Lessons Learned

Following investigation and response, detection coverage should be reviewed to identify opportunities for improvement.

Lessons learned include:

- Centralized logging improves security visibility.
- SIEM filtering helps analysts investigate large volumes of events.
- Authentication and privilege events should be correlated.
- High-severity account changes require immediate investigation.
- Endpoint evidence should be used to validate SIEM alerts.
- Detection rules should be continuously reviewed and improved.

## Incident Response Workflow

Alert → Triage → Investigation → Correlation → Containment → Eradication → Recovery → Lessons Learned

## Conclusion

The incident response phase demonstrated how security alerts generated by Wazuh can be investigated and converted into structured response actions.

The exercise provided practical experience in alert triage, event correlation, incident analysis, containment planning, eradication, recovery, and post-incident improvement within a SOC environment.
